Background

System Evolution

From paper records to an AI-enhanced digital platform — a journey of continuous improvement led by the Quality Team.
Era 1 — Manual

Paper-Based Records

Handwritten ISBAR handover forms, paper shift logs, physical file storage. Manual counting and tabulation for reports.

⚠ Limited search, no analytics, physical storage risk, data loss on damage
Era 2 — Spreadsheet

Excel-Based Tracking

Shift logs moved to Excel spreadsheets. Basic formulas for attendance counting. Email-based report sharing.

⚠ No real-time access, version conflicts, single-user editing, no mobile support
Era 3 — Desktop App

Python Executable System (v1 & v2)

Custom desktop application with local SQLite database. Form entry, basic reporting, shift tracking. Reached version 2.

⚠ Stack not open-source, DB lost on computer format, single-machine, no remote access
Era 4 — Web v1

First Web-Based System

Browser-based access, PostgreSQL database, multi-user support. Core ISBAR forms and resource management.

⚠ Limited features, basic UI, no AI, no scheduling, minimal analytics
Era 5 — Web v2 (Current)

AI-Enhanced Web Platform

Full-featured clinical system with AI insights, advanced scheduling, custom dashboards, Ethiopian calendar, EMR integration readiness. Open-source stack.

Why Version II?

  • Rapid AI advancement — integrating LLM-powered clinical insights
  • Previous limitations removed — open-source stack, cloud-ready
  • Quality Team collected feedback from all departments
  • Ethiopian calendar native support
  • Advanced scheduling with conflict detection
  • Real-time shift tracking and handover workflows

Development Approach

Built by the Quality Team with suggestions collected from clinicians, nurses, midwives, lab staff, pharmacists, and administrators across all departments at Adare General Hospital.

The ISBAR Communication Framework

Standardized clinical handover methodology — the foundation of this system.
I
IDENTIFICATION
Patient name, MRN, age, gender, bed number, attending physician
S
SITUATION
Current condition, presenting complaint, what is happening now
B
BACKGROUND
Medical history, allergies, medications, relevant history, diagnosis
A
ASSESSMENT
Clinical findings, vitals, stability status, risk factors, working diagnosis
R
RECOMMENDATION
Plan of care, next steps, pending tasks, follow-up required

📝 How ISBAR Works in the System

  1. Staff navigates to Report / ISBAR in sidebar
  2. Selects an active form template for their department
  3. System auto-detects checked-in staff as reporter
  4. Fills in each ISBAR section using dynamic form fields
  5. MRN entry auto-populates patient data from previous records
  6. Coded values via ICD-11 / LOINC terminology picker
  7. Skip logic shows/hides fields based on previous answers
  8. Calculated fields auto-compute (e.g., BMI, risk scores)
  9. Form submitted with shift session link and timestamps

🧠 Smart Form Features

  • Skip Logic — Conditional field visibility (e.g., show "Allergy Details" only if "Has Allergies" = Yes)
  • Calculated Fields — Auto-computed formulas with dependency tracking
  • MRN Lookup — Type MRN → auto-fill name, age, gender, bed, diagnosis, allergies
  • Section Collapsing — Color-coded sections with field count badges
  • Terminology — ICD-11, LOINC, UCUM coded values with search
  • AI Stripping — AI-generated content removed before storage for privacy

Localization

Ethiopian Calendar Integration

Native support for the Ethiopian calendar (Ge'ez calendar) throughout the system — dates, holidays, and the Bahire Hasab algorithm.

📅 Calendar Conversion

  • 13 Months — 12 months of 30 days + Pagume (5-6 days)
  • New Year — Meskerem 1 (Sep 11/12 Gregorian)
  • Leap Year — Year % 4 === 3 (adds day to Pagume)
  • Time — 12-hour clock starting at 6 AM GMT (Ethiopian time)
Gregorian ↔ Ethiopian Amharic Month Names 12h Ethiopian Time

🧮 Bahire Hasab Algorithm

Computes the date of Fasika (Ethiopian Easter) using the traditional algorithm:

a = (19 × year + 16) % 30
b = (2 × x + 4 × y + 6 × a + 6) % 7
day = 22 + a + b → month 6 or 7

From Fasika, all movable holidays are computed (Ash Wednesday, Palm Sunday, Good Friday, etc.)

Security

Security & Audit Trail

Multi-layer security approach with authentication, authorization, encryption, rate limiting, and comprehensive audit logging.

🛡️ Security Layers

  • Password Hashing — bcrypt with 10 salt rounds. Legacy plain-text migration supported
  • PIN Hashing — Same bcrypt treatment as passwords
  • JWT Tokens — 7-day expiry, HS256 algorithm
  • Rate Limiting — 8 login attempts per 15 minutes per IP
  • RBAC — Role-based access with hierarchy levels
  • Permission Matrix — Module-level CRUD permissions per user
  • CORS — Production restricted to csms.melesets.com
  • Integration Safety — External HTTP calls restricted to GET-only
