Advanced Forms

Skip Logic & Calculations

Intelligent form behavior — fields appear or hide based on previous answers, and computed values are calculated automatically.

🔀 Skip Logic Engine

Conditionally show/hide fields based on user input. Supports complex logic chains.

OperatorExample
equalsShow "Allergy Details" if "Has Allergies" = "Yes"
not_equalsHide "Pregnancy Notes" if "Gender" ≠ "Female"
containsShow "Diabetes Management" if "Diagnosis" contains "diabetes"
greater_thanShow "Critical Alert" if "Heart Rate" > 120
less_thanShow "Low BP Protocol" if "Systolic BP" < 90
is_emptyShow "Initial Assessment" if "Previous Visit" is empty

Logical operators: AND / OR for combining multiple conditions.

🧮 Calculation Engine

Auto-computed fields with formula support and dependency tracking.

// BMI Calculation
formula: "weight / (height * height)"
fields: ["weight", "height"]
resultField: "bmi"

// Risk Score
formula: "(age > 65 ? 2 : 0) + (hasDiabetes ? 1 : 0) + (bp > 140 ? 1 : 0)"
resultField: "riskScore"
  • JavaScript-style expressions
  • Automatic dependency tracking
  • Recalculates when inputs change
  • Results stored in form_data JSONB

🔍 Terminology Integration

  • ICD-11 — 30+ common diagnoses pre-seeded
  • LOINC — 30+ vital signs and lab codes
  • UCUM — 40+ unit of measure codes
  • ConceptPicker component for coded-text fields
  • Search across systems via /api/terminology/search

Dashboard Form Mapping

Configure how form template fields map to dashboard display cards — control what clinicians see on the main dashboard.

🗺️ Mapping Configuration

  • Source — Select a form template
  • Dashboard Type — Patient card or Resource card
  • Display Name — What appears on the dashboard
  • Department(s) — Which departments see this mapping
  • Profession — Optional profession filter
  • Group By Field — Field used to group records
  • Card Fields — Which fields appear on the card (primary, secondary, status, identifier, nurse)
  • Toggle — Enable/disable without deletion
  • Sort Order — Control display order

📊 Card Field Slots

Secondary Field
Subtitle (e.g., MRN, Age)

🔗 How It Connects

Form Template → Dashboard Mapping → Dashboard Card Display
Staff submits form → Data stored in form_submissions
Dashboard queries mappings by department + profession
Patient cards rendered with mapped field values

📅 Schedule Grid

  • Matrix view — Staff (rows) × Dates (columns)
  • Color-coded shift types — Day (blue), Night (purple), Evening (amber), Off (gray), On-Call (teal), Leave (red)
  • Grouped by profession — Collapsible profession headers

📤 Export Options

⚠️ Conflict Detection

Automated checks on every schedule create/update:

Conflict TypeDescription
Double BookingSame staff assigned to two shifts on same date
UnavailableStaff has approved time-off for that date
UnderstaffedBelow minimum staffing threshold for that shift

Conflicts generate warnings (not blockers) — admin can override if needed.

📏 Minimum Staffing Rules

  • Per shift type, per department, per day-of-week
  • Special holiday staffing rules
  • System warns when schedule falls below minimums

📝 Change Log

Every schedule mutation logged with: who changed, when, old shift type → new shift type. Full audit trail viewable in Change Log modal.

Patient Data

Patient Data Extraction & Normalization

Intelligent patient record extraction from form submissions with field name normalization and MRN-based indexing.

🔍 How Patient Data Works

  1. Staff submits clinical form with patient data
  2. Data stored as JSONB in form_submissions
  3. System extracts MRN from form fields
  4. Groups submissions by unique MRN
  5. Returns latest submission per patient
  6. Normalizes field names across naming conventions
  7. Patient appears on Dashboard with mapped fields

🔗 API Endpoints

GET /api/patient-dataList all patients (by department)
GET /api/patient-data/mrn/:mrnSingle patient detail
GET /api/patient-data/mrnsList all MRNs with names

📝 Field Name Normalization

The system recognizes 10+ naming variants for each field:

🔍 Patient Search

Full-text search across: MRN, patientName, bedNumber, age, gender, diagnosis, allergies. Used by the Dashboard global search and Database Records page.

Summary

Complete System Workflow

End-to-end workflow from system setup to daily clinical operations.

🏗️ Setup Phase (Admin)

1. Install system (Node.js + PostgreSQL)
2. Auto-migrations create all tables on startup
3. Create departments and staff accounts
4. Set PINs for all staff members
5. Create form templates in Form Builder
6. Configure Dashboard Form Mappings
7. Create Custom Tabs if needed
8. Build staff schedules
9. Configure integrations (optional)
10. Set theme and notification preferences

🏥 Daily Clinical Operations

1. Staff logs in with profession
2. Checks in via PIN at Department Panel
3. Views Dashboard for patient overview
4. Submits ISBAR/Clinical forms
5. Updates resource quantities as needed
6. Completes handover during window
7. Checks out at shift end
8. AI generates insights in background
9. Admin reviews analytics and attendance
10. System auto-checkout if forgotten

📊 Reporting Phase

1. View Trends & Analytics dashboard
2. Check Attendance Reports for compliance
3. Review Check-in Logs for patterns
4. Generate AI Clinical Insights
5. Export data (Excel/CSV) for meetings
6. Schedule PNG for wall display

🔧 Maintenance Phase

1. Regular backups via Admin Settings
2. Review audit trail for security
3. Update form templates as protocols change
4. Manage user accounts and permissions
5. Monitor system health
6. Clear expired resources and old reports
